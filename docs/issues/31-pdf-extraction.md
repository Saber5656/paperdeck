# Title

[W4] 31 Implement PDF extraction (text, char boxes, page bitmaps)

## Summary

Implement `src/paperdeck/engines/pdf/extract.py`: pypdfium2-based extraction of per-page
characters with bounding boxes, page geometry, and on-demand 2× page bitmaps, with input
caps, per DESIGN §13.1.

## Context

Foundation of the pdf engine: everything downstream (clustering, LLM segmentation,
equation/figure crops) consumes this module's output.

## Scope

- `open_pdf(path: Path, limits) -> PdfDoc` (context manager owning the pypdfium2 handle).
- `PdfDoc.page_count`, `PdfDoc.chars(page_i) -> list[Char]`
  (`Char = {text: str, bbox: (l,b,r,t) in PDF points, font_size: float}`),
  `PdfDoc.page_size(page_i) -> (w,h)`,
  `PdfDoc.bitmap(page_i, scale=2.0) -> PageBitmap` (lazy, LRU ≤ 8 pages),
  `PageBitmap.crop_png(bbox_points, pad_pt=6) -> bytes`.

## Detailed Requirements

1. Up-front caps before any parsing beyond the header: file size ≤ `limits.max_input_mb`
   (`InputError("pdf-too-large")`); after open: `page_count ≤ limits.max_pdf_pages`
   (`InputError("pdf-too-many-pages")`).
2. Failure taxonomy: password-protected → `InputError("pdf-encrypted")` with hint;
   pypdfium2 load errors → `InputError("pdf-unreadable")`; per-page extraction errors →
   skip page + warning `pdf-page-failed:<i>` (max 10% of pages may fail, else
   `ConversionError("pdf-too-broken")`).
3. Char extraction via the pdfium text page API (`get_charbox` loop); glyphs with empty
   text or zero-area boxes dropped; text normalized NFC; font size approximated from box
   height when the API lacks it.
4. Bitmaps rendered at `scale` (2.0 default ⇒ 144 dpi-equivalent), RGB, no alpha;
   `crop_png` converts point-space bbox to pixel-space (y-flip: PDF origin bottom-left,
   raster top-left — the single documented place this conversion happens), pads, clamps to
   page, encodes PNG via pypdfium2 bitmap `to_pil`-free path (pypdfium2's own PNG save or
   raw→PNG via stdlib `zlib`+struct writer — no Pillow, ADR-005 context; a tiny PNG
   encoder utility is in scope here and unit-tested).
5. Resource hygiene: all pdfium objects closed deterministically (context manager +
   `close()` idempotent); LRU eviction closes bitmaps.
6. Determinism: char order = pdfium text-page index order (documented).

## Acceptance Criteria

- Fixture PDFs (generated by a committed `tests/fixtures/pdf/make_fixtures.py` using
  reportlab, run at test-session setup — binaries not committed): 2-page text PDF (char
  boxes non-empty, ordered, page sizes right).
- SEC-AC (T3 blast-radius limits): encrypted PDF → `pdf-encrypted`; 501-page PDF →
  `pdf-too-many-pages`; oversized file → `pdf-too-large`; truncated/garbage bytes →
  `pdf-unreadable` — each without crashing the process.
- Per-page failure path: a fixture with one corrupt page (bytes patched / extraction
  monkeypatched) yields warning `pdf-page-failed:<i>` and continues; monkeypatched
  failure on >10% of pages raises `ConversionError("pdf-too-broken")`.
- Crop test: render a page containing a black rectangle at known points-coords; crop it;
  decode PNG (stdlib zlib) and assert ≥ 95% dark pixels — proves the y-flip math.
- PNG encoder unit tests: 1×1 and 100×50 RGB round-trip decodable (zlib+struct reference
  decode in test).
- LRU eviction asserted (mock close counting).
